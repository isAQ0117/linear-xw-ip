# Linear xW IP 标准基线冻结记录

**发布标识**：XW-BASELINE-2026-10-28 / V1.0  
**决定**：用户明确批准将上一轮阶段 0 未冻结条款的解决方案直接作为冻结规则。  
**技术契约状态**：`CONTRACT_FROZEN_V1.0`。  
**工程验证状态**：`RTL_HDL_VERIFICATION_PENDING`。

## 当前生效的标准

1. **XW-DEV-STD-001 V1.0** — 《Linear xW IP 九阶段开发与验收标准》：固定阶段 0→8 的顺序、边界和验收原则，开发过程中不随意更改。
2. **XW-CONTRACT-STD-001 V1.0** — 《Linear xW IP 接口与验证契约标准》：冻结顶层 ABI、Job/Status/Error、Reset、AXIS、DDR、B3-B-FP32 数值及三层验证合同。
3. **RTL House Style / Source Preflight** — 作为辅助编码与源码准入制度；不能覆盖上面两项已冻结的架构/行为标准。

## 版本效力说明

- 过去《阶段 0 冻结审计报告》中的“尚待用户批准”状态已被本次明确批准取代，其历史问题记录仍可参考，但不能作为当前技术契约状态。
- 九阶段标准 V1.0 原末章记录的 `阶段0 IN_PROGRESS` 是批准前的**工程进度快照**。本次**技术规则已经冻结**；实际源码前置审计、外部 DDR 平台能力登记与 RTL 仿真仍可为 `PENDING`。这不改变阶段数量、名称、职责和顺序。
- 本次冻结**未新增首版顶层端口，未修改 B3-B-FP32 的数值目标，未宣称 HDL 通过**。

## 平台与材料的条件性准入

- `DDR_MAX_BURST_BEATS`、DDR 最大合法响应等待/间隙、旧响应清理/控制器复位保证尚须从目标平台取得依据并登记；此为**平台参数补全**，不是重新商定规则。
- 已确认能读取本轮提供的原始 FP32 V0.2 完整工程和 RTL Starter；但之前交付的最新 `ffn_style` 重新排版版 ZIP 未在本轮附件中可读取，因此下一次正式修改 RTL 前必须重传/核验该基线。
- Python 历史 12/12 通过不等于 RTL 的真实 HDL 编译/仿真通过。相关工作按阶段 1 开展。

## 固定的后续工作顺序

**先完成阶段 0 的平台/文件归档手续，再严格进行阶段 1 的四个基础 RTL 模块对齐、编译和测试；阶段 2～8 不提前冒充已验收。**

任何改变上述冻结约束的提案，必须由用户明确批准，形成可审计的新版本，而不是以讨论内容直接覆盖标准文件。
