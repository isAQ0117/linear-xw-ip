1. 顶层架构、参数与接口 ABI
1.1 固定的首版形态
IP 名称：
linear_xw_ip
；单 Active Job；先缓存当前 Job 的全部 X，按 N Group 读取 FP32 Scale、按通道读取完整 Weight Row，再按 K Block 顺序计算。
首版策略：
M=1
、
MAX_M_TILE=1
、
P_N=1
、
P_K=8
；无 DDR / Compute 重叠；整个 Job 数值计算完成之后才按 Row-Major 输出。
顶层保留动态尺寸物理接口。
STATIC_DIM_MODE=1
 时，实际 N/K 为编译参数 
N_DIM/K_DIM
，
忽略
物理输入 
job_n/job_k
 的数值，不因其值为 0 或与静态配置不同而拒绝合法 Job。
STATIC_DIM_MODE=0
 时，实际 N/K 在 Job 接受时从 
job_n/job_k
 锁存并进行上下界检查。
第一版 
job_m
 与 
job_m_tile
 均必须为 1；其他值返回 
UNSUPPORTED_JOB
，实际多 Batch / M_TILE 功能只在固定路线的阶段 8 扩展。
使用 Vivado 2023.2、纯 Verilog-2001 保守子集；保持 FFN 风格 ANSI 端口、四空格缩进及按功能分组声明。

2. Job / Status 生命周期（强制）
2.1 单任务执行顺序
IDLE → VALIDATE → LOAD_X → (LOAD_SCALE → LOAD_WEIGHT → B1/B2/A2 → GROUP_REQUANT)* → OUTPUT → STATUS → IDLE
。
其中括号代表依照 N Group / Channel / K Block 顺序重复；整体必须符合已冻结的第一版数据访问次序。内部具体 FSM 状态名称可以不同，但对外可观察行为必须等价。
2.2 Job 接受与配置
1. 
只有 
job_valid && job_ready
 在 
clk
 上升沿同时为 1 时，Job 才被接受。此沿锁存 Job ID、M/N/K/M_TILE、Weight/Scale DDR 基地址及运行配置。已接受 Job 执行期间不得使用未经锁存的外部参数。
2. 
job_ready
 仅在 IDLE 且未处于系统故障锁定时置 1。第一版不接受第二个未完成 Job，不实现排队。
3. 
非法 Job 必须可以被接受，然后返回失败 Status
；不得因为输入 N/K/M_TILE 非法而让 
job_ready
 永久保持 0。静态模式物理 
job_n/job_k
 不参与合法性验证。
4. 
验证错误在任何 DDR/AXIS 数据传输之前产生；若为可恢复配置错误，进入 STATUS，交付失败后允许正常重新接单。
2.3 Status 与 Busy
1. 
每个已接受的 Job 必须且只能对应
一个最终 Status
。
status_valid
 有效后，
status_job_id
、
status_ok
、
status_error_code
 必须保持稳定，直到 
status_valid && status_ready
 的上升沿握手。
2. 
busy
 从 Job 被接受后置 1，保持到最终 Status 被接受；普通任务在 Status 握手后返回 IDLE，
job_ready
 最早在后续周期重新有效。
3. 
成功：
status_ok=1
 且 
status_error_code=0x00
。失败：
status_ok=0
 且错误码非零。
4. 
最后一个输出 Beat 发生 
m_axis_tvalid && m_axis_tready
 有效握手后，才允许发布成功 Status：若该输出握手在上升沿 
t
，
status_valid
 最早于 
t
 后变为 1，状态握手最早发生于 
t+1
 上升沿。
5. 
正常计算阶段发现失败时，由于首版 OUTPUT 在整个 Job 计算完成后才启动，
不得向下游发送该失败 Job 的输出 Beat
；清理内部有效标记并进入 STATUS。复位若发生于已开始输出之后，下游已收到的部分结果无法撤销，需由上层按 Job ID 丢弃。
6. 
处于 
FAULT_LOCK
 时，
job_ready=0
。若已有被接受的 Job，则先交付其失败 Status；Status 握手后 
busy=0
 且继续保持锁定，直到外部清理并复位。
7. 
在没有活动 Job 的 IDLE 时检测到不可归属的 DDR 故障，不得制造虚构 Job ID 或伪造 Status；进入 
FAULT_LOCK
，需要系统层诊断和恢复。

3.2 处理优先级与安全退出
1. 
首个错误锁存
：一旦确定当前 Job 的首个错误，不得被以后到达的次要错误覆盖。同一个时钟沿多种错误同时首次出现时，优先锁存会导致系统失同步/故障锁定的错误；同一恢复类别内按上表先后顺序选择最先匹配者，保证软件/RTL 输出确定性。
2. 
任务级恢复须满足干净边界
：已接收的输入 Tensor 完整且无需继续重新同步；没有未完成 DDR 请求，也不存在迟到响应；对应内部 Buffer 被作废。满足时错误 Status 完成交付后可以接收新任务，否则升级为系统级故障锁定。
3. 
AXIS 格式与序列错误默认
不自动尝试 EOT 重新同步
，因为 EOT 可能正是错误内容；上层负责清理流并协调复位。
4. 
DDR 协议、响应失同步、Timeout 和内部不可恢复错误进入 
FAULT_LOCK
；绝不能仅在下一请求到来时自动清除错误并继续接收 DDR。
5. 
错误码代表可检测的异常；没有 Response ID / Last 的物理接口
无法保证所有 DDR 错误都可以被识别
，此限制必须出现在系统集成说明和验证报告中。
4. Reset 与故障恢复
1. 
rst_n
 低有效，
异步断言、在 `clk` 域同步释放
（推荐两级释放同步）。所有同一时钟域的状态机、Valid 标记、计数器和任务所有权按照此规则恢复。
2. 
Reset 清除本地 Job、尚未交付的 Status、可观察 Valid、事务计数及 Buffer 有效标记；
大容量 BRAM / RAM 数据位不要求逐位清零
，但不得将旧内容作为新任务有效数据。
3. 
Reset 不具备取消已被外部 DDR Controller 接受的请求的能力。若有旧响应在途，外部系统必须先
清空或复位外部 DDR 事务域
，确保不会把旧数据交给复位后的新任务。
4. 
系统级恢复顺序固定为：停止分配新任务 → 当前可归属任务报告失败（若接口仍可交付）→ 进入 
FAULT_LOCK
 → 上层清理 DDR 和 AXIS 事务 → 受控 Reset → 确认外部事务域干净 → 重新进入 IDLE。
5. 
仅重置 Linear IP 不能保证 DDR 链路恢复。
 如果平台不提供旧响应清理/复位保证，系统不得声称具备完整的故障自动恢复能力；此为集成前置条件，不通过增加首版顶层端口规避。

5.2 合法 Beat 与反压
1. 
当前 Group 余下 
r
 个元素时，本 Beat 有效元素数 
L=min(28,r)
，有效字节 
B=ceil(18L/8)
；
TKEEP
 必须为低 
B
 位连续为 1，其余为 0。所有 Padding bit 必须为 0。
2. 
Row、Group、Offset 必须与按 Row-Major / K-Group 顺序计算的期望游标相同；
group_len
 与有效 K（输出时为 N）的实际尾组长度相同。
shared_exp
 在同一 Group 的每一个 Beat 中保持一致。
3. 
TLAST
 仅在当前 BFP Group 的最后一个 Beat 有效；EOT 只在整个 Tensor 的最后一个 Beat 有效；Reserved bit 必须为 0，
job_id
 必须对应已接受 Job。
4. 
上游可在 Beat 之间任意停顿；不得因正常空隙报错。
TVALID && !TREADY
 期间，上游必须保持 TDATA/TKEEP/TLAST/TUSER 稳定；输出侧同样必须保持全部这些字段及 TVALID 稳定，直到发生握手。
5. 
输入 Parser 只能在 
TVALID && TREADY
 的上升沿消费一个 Beat；不能使用尚未握手的 TUSER 或 DATA 更新逻辑游标。
6. 
不符合格式、序列或 EOT 的输入按第 3 节对应错误码报告，触发流同步失效，不自动恢复。
6. DDR 六信号协议与 Layout V3
6.1 物理合同
1. 
DDR 端保持六信号和 512-bit 返回，不增设 
ready/last/id
；逻辑地址 29-bit，每 Beat 地址步长为 8，
ddr_rd_addra
、
ddr_rd_addrb
 定义
包含式
 Range。
2. 
同时最多一个 Outstanding Range；必须等待该 Range 按约定 Beat 数完整接收，才能接受下一 Range。DDR 返回允许 Beat 间隙；Receiver 端没有回压，
ddr_rd_vld=1
 时必须无条件接收完整 512-bit 数据。
3. 
DDR 请求通过 
ddr_rd_req && ddr_rd_rdy
 在上升沿被接受；待发的内部 
cmd_valid
 及地址/Beat 数应保持到接受时。
首个数据 Beat 可以在请求接受的同一上升沿出现
，接收端不得丢失。
4. 
无 Response ID/Last 使得请求边界依赖预期 Beat 数和外部控制器正确行为。外部 DDR 必须保证响应顺序、数量和不混入其他事务；系统集成需要单独核实该约束。
6.2 DDR Layout V3 与地址公式
Weight：FP8 
[N,K]
，输出通道主序、同一行 K 连续，
每 Weight Row 独立 64 Byte 对齐
。
Scale：每 128 输出通道为一个 N Group；每 Group 有 
ceil(K/128)
 个 FP32 原始 32-bit 值，little-endian 保存，16 个 FP32 / 512-bit Beat，
每 Group 独立 64 Byte 对齐
。
设 
RW=ceil(K/64)
、
RS=ceil(K/2048)
、
G=ceil(N/128)
、
J=ceil(K/128)
。第 
n
 个 Weight Row 的起始地址：
AW(n)=job_weight_base+8*n*RW
；第 
g
 个 Scale Group 的起始地址：
AS(g)=job_scale_base+8*g*RS
。
任意物理 Range 的包含式 End：
Aend=Astart+8*(R-1)
，其中 
R
 为本次读取 Beat 数。
使用足够宽的内部表达式运算，检查地址后才允许截为 29-bit
。
Base 地址必须按 8 对齐，整段 Weight / Scale 不得越界或相互重叠。末端独占边界允许等于 
2^29
，但每次实际发送的 Start/End 均必须在 29-bit 合法范围内。
6.3 Burst 分段、Timeout 与故障
1. 
“完整读取 Weight Row 后才计算”是
逻辑行为
，不要求物理上只能使用一次 Range。如果实际 DDR Controller 不支持一行的完整 Burst，地址生成器必须按平台 
DDR_MAX_BURST_BEATS
 分段，依次读取并完整拼回 Weight Buffer；Scale 也遵守该上限。
2. 
DDR_MAX_BURST_BEATS
、请求响应最大合法时延、控制器重置/旧响应清理保证，登记到
平台配置档案
；不能凭以前 FFN RTL 中的示例请求长度推断硬件保证。物理分段方式一经登记必须与 Python Microarchitecture Cycle Model 一致。
3. 
第一版功能 RTL 默认不启用 DDR 硬件 Timeout。
 Testbench 应设置仿真超时避免无限等待。以后只有取得外部控制器最大延迟保证，才允许启用可配置 Watchdog；触发 
DDR_TIMEOUT
 后必须故障锁定，不得自动发下一请求。
4. 
若没有硬件 Timeout，缺失响应可能导致 Job 长期等待；不承诺在任意损坏的 DDR 环境中自动前进。实际系统应由系统层监测并在必要时执行受控恢复。
5. 
xw_ddr_range_rx.v
 中现有“下一笔命令到来时清除 sticky range_error”的实现不符合本合同的故障锁定语义，必须在
阶段 1

7.2 A2 与 Requant 必须 Bit-Exact
1. 
A2 每接收到一个 K Block 的 Term 就执行一次 48-bit 有符号状态舍入与归一化。

2.

3.

131071

5. 
禁止将非法 FP8/Scale、A2 指数超界、输出 BFP18 指数超界静默地转换为零、替代 Scale、饱和或忽略；必须按

6. 
对来自 DDR 的非法值，若错误发生时 Range 尚未完成，先确保本次返回能够完整安全收尾；无法确认干净 DDR 边界时必须升级为
